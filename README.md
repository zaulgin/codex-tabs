# Codex Tabs

Дополнение к официальному расширению `openai.chatgpt`: открывает его чаты в отдельных вкладках редактора и предоставляет выбор разговоров из общей локальной истории CLI/IDE.

Это прототип на внутреннем механизме официального расширения, а не продукт OpenAI. Установленные файлы Codex не изменяются, его код не включается в пакет.

## Команды

В палитре команд (`Ctrl+Shift+P`):

- **Codex Tabs: New Chat in Tab** — новая вкладка официального Codex.
- **Codex Tabs: Open Chat from History** — поиск по заголовкам и постраничная загрузка истории; выбор открывает разговор в официальном редакторе.
- **Codex Tabs: Open Chat by ID** — открытие разговора по ID из `/status`.

История также доступна по кнопке с часами в верхней панели редактора каждой вкладки Codex. Она открывает общий список с поиском; встроенной боковой панели истории в официальном редакторе вкладки нет. Поиск использует `thread/list.searchTerm` Codex (по заголовкам, не по тексту сообщений). `Load more conversations…` загружает следующую страницу. Уже открытый разговор с URI `/local/<id>` фокусируется в своей группе редакторов.

## Установка и разработка

Нужны VS Code 1.96+ и официальное расширение Codex. Для разработки и упаковки нужен Node.js 22.9+; для использования установленного VSIX отдельный Node.js не требуется.

```sh
npm ci --ignore-scripts
npm test
npm run package
```

Результат: `codex-tabs-0.1.1.vsix`. В VS Code выполните **Extensions: Install from VSIX…** и выберите файл, затем **Developer: Reload Window**. Для разработки можно открыть этот репозиторий и запустить конфигурацию **Run Codex Tabs** через F5; официальный Codex должен быть доступен в окне Extension Development Host.

При Remote SSH дополнение должно работать в SSH-окружении рядом с официальным Codex. В Extensions проверьте раздел **SSH: ваш сервер**. Интерфейс чата показывается на локальном компьютере Windows, а запросы истории выполняются на сервере.

## Как это устроено

Официальный custom editor `chatgpt.conversationEditor` получает URI `openai-codex://route/extension/panel/new?instance=<uuid>`. Уникальный ресурс нужен, потому что официальная команда переиспользует постоянный URI. Существующий разговор открывается по `openai-codex://route/local/<id>`.

Перед открытием проверяется наличие нужного editor contribution и активируется официальный Codex. Очередь, корректировки во время работы, разрешения, модели, IDE-контекст, ссылки и изображения остаются в официальной реализации; сохранение их поведения в нескольких вкладках необходимо проверить вручную.

При открытии истории запускается временный App Server. Дополнение отправляет только `initialize` и `thread/list`, не запускает и не возобновляет задачи, не разрешает серверные запросы действий. После выбора, отмены, ошибки или таймаута вспомогательный процесс закрывается. Тексты чатов, stderr и ошибки сервера не записываются в логи дополнения.

История читается из индекса Codex (`useStateDbOnly: true`): поиск и страницы не запускают повторное сканирование JSONL-файлов и восстановление метаданных. На большой истории это сканирование могло превышать таймаут 15 секунд. Чаты, которые сам Codex ещё не добавил в индекс, появятся после его штатной индексации. При сбое показывается безопасное сообщение о конкретном типе ошибки: запуск, соединение, таймаут или ответ сервера.

Ограничение касается RPC: сам App Server при старте может инициализировать своё хранилище и выполнять штатные фоновые действия. Telemetry вспомогательного процесса выключается аргументами; `config.toml` не редактируется. Credentials и файлы переписок дополнение напрямую не читает.

По умолчанию используется тот же executable, что у официального Codex: `chatgpt.cliExecutable`, если задан, иначе bundled binary. Машинная настройка `codexTabs.cliPath` позволяет задать другой исполняемый файл; это путь, а не shell-команда. Наследуется окружение extension host, включая Codex home. История другого компьютера/другого home и облачная история аккаунта автоматически не объединяются.

Расширение работает только в доверенном workspace. Переименование, удаление, архивация чатов и отдельный agent runtime в дополнение не входят.

## Совместимость и проверка

Статически исследован официальный пакет `openai.chatgpt` версии **26.1111.21308**. Приватные маршруты могут измениться после обновления. Наличие editor contribution проверяется автоматически, но это не доказательство совместимости его внутреннего состояния.

Автоматические тесты проверяют адреса вкладок, проверку ID, фокусирование известного разговора, поиск/пагинацию/отмену истории и JSONL-протокол с синтетическим дочерним процессом. Они не доказывают независимость настоящих сессий официального клиента.

Перед полноценным использованием проверьте в отдельном рабочем окне:

1. Откройте три новые вкладки. Введите разные черновики, отправьте разные простые запросы, сравните ID через `/status`. Черновики, ID, ответы и состояния выполнения должны различаться.
2. В двух вкладках одновременно проверьте очередь и корректировку текущего задания, остановку и запросы разрешений. Действие должно относиться только к выбранному разговору.
3. Откройте существующие CLI/IDE разговоры из истории, загрузите следующую страницу, выполните поиск. Повторное открытие известного разговора не должно создавать второй экземпляр.
4. Проверьте активный файл и выделение в IDE-контексте, переход из ответа к файлу и строке на SSH-сервере.
5. На Windows скопируйте снимок экрана в системный буфер, вставьте через Ctrl+V в чат Remote SSH. Проверьте предпросмотр, отправку и получение изображения агентом.
6. Закройте/восстановите вкладки и перезагрузите окно. Проверьте историю и отсутствие самопроизвольной повторной отправки. Поведение активной задачи при закрытии определяется официальным клиентом.

Реальный Windows → Remote SSH сценарий ещё не проверен. Если новый URI создаёт только отдельный вид с общим черновиком/разговором, это блокирующий дефект подхода; не используйте его для параллельного редактирования до исправления. Репозиторий и VSIX предназначены для проверки этой гипотезы.
